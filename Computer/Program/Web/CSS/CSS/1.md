#介绍

##Web 样式简介

​		1994 年，正值 Web 开始广泛流行开来，CSS 的第一个提案发布了。CSS 就是在这样的背景下诞生的，它的目标是提供一个简单的声明式样式语言，而且具有一定的灵活性。其名称中的层叠指样式可以结合起来使用，而且具有优先级。

​		1996 年年末，CSS1 完成了。此后，刚组建的 CSS 工作组开始着手制定 CSS2。单独来看，CSS 的每一部分都很简单，但把各个部分放在一起就变得异常复杂。而且早期实现有些先天不足，如不同浏览器对盒模型（box model）的实现之间的差异尤其为人诟病。这些问题直接影响到 CSS 的名声，幸好一些聪明人提出了变通方法，让浏览器的行为保持了一致。得益于一致性的提高和高调的开发活动，如使用 CSS 重新设计 Wired 杂志和 CSS Zen Garden，几年之间，CSS 逐渐开始流行。

​		不过，在此之前，CSS2 规范于 1998 年年初定案。随后，CSS 工作组立即投身 CSS3 的制定工作，以及 CSS2 的修订工作（制定 CSS2.1）。与以往不同的是，CSS3 由多个（理论上）独立的模块构成，而不是单独一个臃肿的规范。XHTML 规范受此启发，也采用了这种模块式机制。

​		CSS3 分成多个模块的根本原因是各模块可以独立演进，尤其是重要的（或受众广的）模块可以按照 W3C 的规划向前推进，而不必受其他模块拖累。事实证明，这样做是对的。截至 2012 年年初，有三个 CSS3 模块（CSS Color Level 3、CSS Namespaces 和 Selectors Level 3）变成了全力推荐状态，而有七个模块处于候选状态，还有七个模块处在不同的草案状态。如果采用以前的机制，要等其他部分完成才能在一份完成的规范中发布颜色、选择符和命名空间的新条款。得益于模块化，我们无需再等待。

​		但是，这样做也有缺点，即“CSS3 规范”不能涵盖一切。世界上不再有这种叫法，也不可能再有。即便其他模块在某一时刻到达了 Level 3，比如说 2016 年年末（然而并没有），Selectors Level 4 也都开始制定了。那会不会有 CSS4？“CSS3” 那些尚未正式发布的新特性呢？还有 Grid  Layout，它甚至还没到 Level 1。

​		可见，不能指着一摞厚厚的文件说，“这就是 CSS3”，而应该分模块学习不同的特性。模块的灵活性有时可以弥补由此引起的语义不足（如果非要一份独立的完整规范，可以留意 CSS 工作组每年发布的 “Snapshot” 文档）。

##元素

​		元素（element）是文档结构的根基。文档中的每个元素都对文档的表现起一定作用。

###置换元素和非置换元素

​		CSS 依赖元素，但并非每个元素都以同样的方式创建。对 CSS 来说，元素通常有两种形式：置换元素和非置换元素

- **置换元素（replaced element）**：指用来置换元素内容的部分不由文档内容直接表示。最常见的置换元素要数 img，它的内容由文档之外的图像文件替换。该元素没有内容，如果不通过属性指向外部内容，就什么也显示不了。

  input 元素类似，根据类型不同，会替换为单选按钮、复选框或文本输入框

- **非置换元素（nonreplaced element）**：HTML 元素大部分是这种，即元素的内容由用户代理（通常是浏览器）在元素自身生成的框中显示。文本、段落、标题、单元格、列表都是非置换元素

###元素的显示方式

​		除了置换元素和非置换元素之外，CSS 还把元素分成块级和行内两种基本类型。除此之外，还有其他显示类型，不过这两种是最常见的。

- **块级元素**：块级元素（默认）生成一个填满父级元素内容区域的框，旁边不能有其他元素。即，块级元素在元素框的前后都“断行”。置换元素可以是块级元素，但往往不是

  列表项目是一种特殊的块级元素，它的表现与其它块级元素没有区别，此外还会在元素框旁边生成一个记号（如无序列表的圆点、有序列表的数字）。除了多出的这个记号外，列表项目与其它块级元素之间没有任何区别。

- **行内元素**：行内元素在一行文本内生成元素框，不打断所在的行。因此可以出现在另一个元素的内容中，且不影响所在的元素。

​		HTML 中的块级元素和行内元素虽然有诸多共同点，但是块级元素不能出现在行内元素中。但是 CSS 并不限制它们的显示方式，可以相互嵌套。

- ```html
  <body>
      <p>This is a paragraph with <em>an inline element</em> within it.</p>
  </body>
  ```

  这里有两个块级元素（body 和 p）以及一个行内元素（em）。根据 HTML 规范，em 可以放在 p 里，而反过来却不行。一般地，HTML 层次结构要求，行内元素可以放在块级元素中，反之则不行。

- 与此同时，CSS 没有这种限制。在不改变标记的前提下，可以像下面这样改变它们的显示方式

  ```css
  p {display: inline;}
  em {display: block;}
  ```

  这会导致行内框中出现一个块级框。这完全是有效的，不违背任何 CSS 规则。

- 然而，如果在 HTML 中调换元素之间的嵌套关系，就会出问题。下面不管通过 CSS 如何改变显示方式，都不是有效的 HTML

  ```html
  <em><p>This is a paragraph improperly enclosed by an inline element.</p></em>
  ```

##把 CSS 应用到 HTML 上

​		HTML 文档内部有一定的结构。这种结构正是 HTML 和 CSS 之间固有关系的一部分。

###link 标签

​		link 标签的基本作用是把其他文档与当前文档关联起来。CSS 使用它链接应用到文档上的样式表。通过 link 标签链接的样式表不是 HTML 问的一部分，但却供文档使用，称这样的样式表为外部样式表（external stylesheet），因为样式表在 HTML 文档外部。

​		为正确加载外部样式表，link 标签必须放在 head 元素中，不能放在其他元素中。还可以在 style 元素中通过 @import 声明加载外部样式表，@import 声明必须放在所在样式表的开头，此外别无限制。

- index.html

  ```html
  <!DOCTYPE html>
  <html lang="en">
  
  <head>
      <meta charset="UTF-8">
      <meta name="viewport" content="width=device-width, initial-scale=1.0">
      <title>Document</title>
      <style type="text/css">
          @import url(./style.css);
      </style>
  </head>
  
  <body>
      <book>
          <maintitle>Cascading Style Sheets: The Definitive Guide</maintitle>
          <subtitle>Third Edition</subtitle>
          <author>Eric A. Meyer</author>
          <publisher>O'Reilly and Associates</publisher>
          <pubdate>November 2006</pubdate>
          <isbn type="print">978-0-596-52733-4</isbn>
      </book>
      <book>
          <maintitle>CSS Pocket Reference</maintitle>

          <author>Eric A. Meyer</author>
          <publisher>O'Reilly and Associates</publisher>
          <pubdate>October 2007</pubdate>
          <isbn type="print">978-0-596-51505-8</isbn>
      </book>
  </body>
  
  </html>
  ```

- ```css

​		样式表中不能有 HTML 或其他标记语言，只能包含样式规则。外部样式表保存为纯文本文件，扩展名通常是 `.css`。

​		文件扩展名不是必须的，但如果文件名称不以 `.css` 结尾，即使在 link 元素中把 type 属性设置为 text/css，有些旧的浏览器也不会将其识别成包含样式表的文件。其实，如果文件名不以 `.css` 结尾，有些 Web 服务器不会以 text/css 格式伺服问价。不过，修改服务器的配置文件往往能解决这个问题。

####属性

- **rel**：是 relation的简称，指定关系是 stylesheet

- **type**：说明通过 link 标签加载的数据类型，text/css Web 浏览器才知道加载的是 CSS 样式表，然后确定如何处理加载的数据。以后可能会出现其他的样式语言，因此最好声明。

- **href**：值是样式表的 URL，可以是绝对地址，也可以是相对地址。

- **media**：值是一个或多个媒体描述符，指明媒体的类型和具有的功能。多个媒体描述符以逗号分隔。如，可以像下面这样链接针对屏幕媒体和投影媒体的样式表

  ```html
  <link ref="stylesheet" type="text/css" href="visual-sheet.css" media="screen, projection">
  ```

  媒体描述符有时会很复杂。后面继续说明。

​		一个文档可以关联多个样式表，此时，最初显示文档时只会使用 rel 属性的值为 stylesheet 的 link 标签链接的样式表。

####候选样式表

​		如果浏览器支持候选样式表，会使用 link 元素 title 属性的值生成候选样式列表。

###style 元素

​		style 元素也是一种引入样式表的方式，直接写在文档中。style 元素应该始终设定 type 属性，对 CSS 文档来说，正确的值是 `text/css`，与 link 元素是一样的。

​		style 元素也有 media 属性，与通过 link 元素链接的样式表功能一样。开始和结束 style 标签之间的样式称为文档样式表（document styleshett）活嵌入式样式表（embedded stylesheet，因为这种样式表内嵌在文档中）。style 元素可以直接包含应用到文档上的样式，也可以通过 @import 指令引入外部样式表。

###@import 指令

​		可以出现在 style 标签中的内容。首先是链接外部样式表中也要有的 @import 指令。与 link 一样，Web 浏览器遇到该指令时会加载外部样式表，使用其中的样式渲染 HTML 文档。二者之间唯一的主要区别在于句法和指令的位置。可以看出，@import 指令在 style 元素内部，而且必须放在其他 CSS 规则前面，否则不会起作用。

​		与 link 一样，一个文档中可以有多个 @import 语句。然而，不同的是，@import 指令导入的每个样式表都会使用，无法指定候选样式表。

​		与 link 类似，@import 指令也可以显示导入的样式表应用于何种媒体。方法是在样式表的 URL 后面提供媒体运算符

- index.html

  ```html
  <!DOCTYPE html>
  <html lang="en">
  
  <head>
      <meta charset="UTF-8">
      <meta name="viewport" content="width=device-width, initial-scale=1.0">
      <title>Document</title>

###HTTP 链接

​		为文档关联 CSS 还有一种鲜为人知的方式：使用 HTTP 首部。在 Apache 中，若想使用这种方式，可以在 .htaccess 文件中引用 CSS 文件。如

```
Header add Link "</ui/testing.css>;rel=stylesheet;type=text/css"
```

这样设置之后，支持这种方式的浏览器在加载受此 .htaccess 文件管理的文档时便会使用指定的样式表，就像通过 link 元素链接的样式表一样。

​		此外，还可以在服务器的 httpd.conf 文件中添加等效的规则，这样做可能更高效

```conf
<Directory /path/to /public/html/directory>
Header add Link "</ui/testing.css>;rel=stylesheet;type=text/css"
</Directory>
```

在支持这种方式的浏览器中，这样做的效果与前面一样，唯一的区别是设置所在的文件不同。

​		**关于“支持这种方式的浏览器”**：截至 2017 年年末，广泛支持 HTTP 链接样式表的浏览器有 Firefox 系列和 Opera。因此，这种方式最常在使用这些浏览器中的某一款做开发时使用。鉴于此，在测试服务器中使用 HTTP 链接便可以把开发中的网站与线上公开的网站区分开。如果出于特殊的原因，想隐藏一些样式，不让 WebKit 和 Internet Explorer 系列使用，也可以使用这种方式。

​		常用的脚本语言（如 PHP）和 IIS 也有等效的方式，方法是设定 HTTP 首部。此外，还可以使用脚本语言向服务器伺服的文档插入 link 元素。考虑到浏览器的支持，这种方案更牢靠，毕竟所有浏览器都支持 link 元素。

###行内样式

​		如果只想为单个元素提供少量样式，可以利用 HTML 元素的 style 属性设置行内样式。除了 body 元素之外的标签（如 head、title），所有 HTML 标签都能设定 style 属性。

​		style 属性的值只能是一系列规则声明，而不能包含整个样式表。因此，不能在 style 属性中使用 @import 指令，也不能有完整的规则。style 属性的值只能是样式规则花括号之间的那一部分。

​		通常不建议使用 style 属性。而且，除了 HTML，XML 很少使用这个属性。倘若使用 style 属性，CSS 的很多重要优点都不复存在了，如集中管理样式，控制整个文档或网站中所有文档的外观。在很多方面，行内样式都不必 font 标签好多少，不过却提供了一定的灵活性。

###规则的结构

​		一个规则由两部分构成：选择符（selector）和声明块（declaration block）。声明块由一个或多个声明组成，而一个声明包含一个属性（property）和对应的值（value）。一个样式表由一系列规则组成。

​		选择符定义文档中的哪部分受影响。声明块由一个或多个声明组成，一个声明包含一个 CSS 属性及其值。

###厂商前缀

​		有时会发现，CSS 中有些内容的前面有个标注，如 `-o-border-image`。这叫厂商前缀（vendor prefix），浏览器厂商通过它标记实验性或专属（或二者兼具）的属性、值或其他内容。截至 2016 年年末，市面上有不少厂商前缀，如下表展示的一些

​		**表：一些常用的厂商前缀**

| 前缀     | 厂商                                        |
| -------- | ------------------------------------------- |
| -epub-   | 国际数字出版论坛指定的 ePub 格式            |
| -moz-    | 基于 Mozilla 的浏览器（如 Firefox）         |
| -ms-     | 微软 Internet Explorer                      |
| -o-      | 基于 Opera 的浏览器                         |
| -webkit- | 基于 Webkit 的浏览器（如 Safari 和 Chrome） |

厂商前缀的一般格式是一个英文破折号、一个标注和一个英文破折号。不过也有少量前缀不采用这个格式，开头没有破折号。

​		使用厂商前缀的原因复杂，不是三言两语就能说清的。可以说，厂商前缀出现的目的是浏览器厂商为了测试新特性，这么做能保证兼容性，不必担心被过时的行为限制，导致与其他浏览器不兼容。这样做能避免一系列问题，以免遏制 CSS 的发展，网页制作者们后来大量使用带前缀的属性，由此引起了一系列的问题。

​		截至 2016 年年末，厂商前缀的使用趋势有所减缓，因为新版浏览器逐渐删除了对带前缀的属性和值的支持。如今，编写 CSS 时完全可以不使用厂商前缀，不过偶尔会遇到别人使用，或者在以前的代码中见到。

###处理空白

​		CSS 对规则之间的空白基本没有严格要求，而且对规则内部的空白大多也没有严格要求，不过有些例外。

​		一般来说，CSS 对待空白的方式跟 HTML 差不多：解析时，连续的空白会合并成一个空白。因此，虚构的 rainbow 规则可以写成下面这几种格式。

```css
rainbow: infrared red orange yellow green blue indigo violet ultraviolet;

rainbow:
	infrared red orange yellow green blue indigo violet ultraviolet;

rainbow:
	infrared
	red
	orange
	yellow
	green
	blue
	indigo
	violet
	ultraviolet
	;
```

当然，除此之外还有其他分隔方式。唯一的要求是，要使用空白分隔，可以是空格、制表符或换行符，可以是单个空白，也可以任意数量随意组合。同样，规则之间的空白也可以随意使用。其实，有些地方是必须使用空白的。最常见的是使用空白分隔值中的多个关键字。多个关键字必须用空白分开。

###CSS 注释

​		CSS 注释也放在 `/**/` 之间。可以分成多行，但是不能嵌套。CSS 没有 `//` 或 `#` 的单行注释（后者是保留字，用于选择 ID）。

​		对 CSS 解析器来说，CSS 注释相当于根本没出现过，并不算作空白。因此，注释可以放在规则内部，甚至可以放在声明内部。

##媒体查询

​		创作人员通过媒体查询（media query）定义浏览器在何种媒体环境中使用指定的样式表。过去，实现这一机制的方法是通过 link 元素或 style 元素的 media 属性设定媒体类型，或者为 @import 或 @media 指令提供媒体描述符。媒体查询更进一步，允许创作人员通过媒体描述符根据指定媒体类型的特性选择样式表。

###用法

​		媒体查询可以在下述几个地方使用：

- link 元素的 media 属性
- style 元素的 media 属性
- @import 声明的媒体描述符部分
- @media 声明的媒体描述符部分

媒体查询可以是简单的媒体类型，也可以是复杂的媒体类型和特性的组合。

###简单的媒体查询

​		介绍媒体查询的各种可能用法之前，先看几个简单的媒体块。假设想在投影环境（如幻灯片）中使用一些不同的样式。下面是这个 CSS 中比较简单的两个规则

```css
h1 {color: maroon;}
@media projection {
    body {background: yellow;}
}
```

针对这个例子，在所有媒体中，h1 元素的颜色都是红褐色，但是，在投影媒体中，body 元素会有一个黄色背景。

​		一个样式表中可以有任意多个 @media 块，而且每一个都有自己的一套媒体描述符。如果愿意，可以把所有规则都放在一个 @media 块里

```css
@meida all {
    h1 {color: maroon;}
    body {background: yellow}
}
```

然而，这与去掉首尾两行的效果一模一样，完全没必要。

- @meida 块中的规则可以不缩进，如果觉得缩进能让 CSS 更易于阅读，可以缩进。

​		示例中的 projection 和 all 就是设定媒体查询的位置。媒体查询包含描述媒体类型的词组和对媒体参数的说明（如分辨率或显示屏高度），决定块中的 CSS 何时应用。

###媒体类型

​		媒体查询最基本的形式媒体类型，由 CSS2 引入。媒体类型就是指明不同媒体的标注

- **all**：用于所有展示媒体
- **print**：为有视力的用户打印文档时使用，也在预览打印效果时使用
- **screen**：在屏幕媒体（如桌面电脑的显示器）上展示文档时使用。在桌面计算机上运行的所有 Web 浏览器都是屏幕媒体用户代理。

​		有些浏览器支持 projection 类型，能以幻灯片的形式展示文档。有些移动设备的浏览器支持 handheld 类型，但是行为不一致。

​		多个媒体类型使用逗号分隔罗列，下面四种方式都能把一个样式表（或一个规则块）同时应用到屏幕媒体和印刷媒体上

```html
<link type="text/css" href="frobozz.css" media="screen,print">
<style type="text/css" media="screen,print">...</style>
```

```css
@import url(frobozz.css) screen,print;
@media screen, print {...}
```

为媒体类型加上特性描述符（如，描述指定媒体的分辨率或色深）之后事情就变得有趣了。

###媒体描述符

​		下面两种方式都能把指定的外部样式表应用到彩打上

```html
<link href="print-color.css" type="text/css" media="print and (color)" rel="stylesheet">
```

```css
@import url(print-color.css) print and (color);
```

​		能使用媒体类型的地方都能使用媒体查询，意味着可以通过一个逗号分隔的列表列出多个查询

```html
<link href="print-color.css" type="text/css" media="print and (color), screen and (color-depth: 8)" rel="stylesheet">
```

```css
@import url(print-color.css) print and (color), screen and (color-depth: 8);
```

只要其中一个媒体查询的条件得到满足，就会应用指定的样式表。

​		一个媒体描述符包含一个媒体类型和一个或多个媒体特性列表，其中特性描述符要放在圆括号中。如果没有媒体类型，那就应用到所有媒体上，下面写法是等效的

```css
@media all and (min-resolution: 96dpi) {...}
@media (min-resolution: 96dpi) {...}
```

​		一般情况下，媒体特性描述符的格式类似于 CSS 中的一对属性何值。二者之间最大的区别是，特性描述符可以不指定值。因此，任何彩色媒体都符合（color）指定的条件，任何色深为 16 位的彩色媒体都符合（color: 16）指定的条件。其实，不指定值时是在做判断。

​		多个特性描述符使用逻辑关键字 and 连接。媒体查询中可使用的逻辑关键字有两个

- **and**：连接的两个或多个媒体特性必须同时满足条件，整个查询得到的结果才是真值。如 `(color) and (orientation: landscape) and (min-device-width: 800px)` 表示三个条件都要满足：当媒体环境是彩色的、横向放着，而且设备的屏幕宽至少为 800 像素，才会应用样式表。
- **not**：对整个查询取反。假如所有条件都为真，那样式表不会应用到文档上。如，`not (color) and (orientation: landscape) and (min-device-width: 800px)` 表示三个条目都满足时，整个语句得到的结果与之相反。因此，当媒体环境是彩色的、横向放着，而且设备的屏幕宽至少为 800 像素，样式表不会应用到文档上。除此之外的情况下，都将应用样式表。

not 关键字只能在媒体查询开头使用。写在其它位置，媒体查询将被忽略。太久的浏览器不支持媒体查询，因此会跳过媒体描述符以 not 开头的样式表。

​		媒体设备不支持 OR 关键字。不过，分隔多个媒体查询的逗号相当于 OR。如，`screen, print` 的意思是“为屏幕或印刷媒体时应用样式”；`screen and (max-color: 2) or (monochrome)` 是无效的，会被忽略。正确的写法是 `screen and (max-color: 2), screen and (monochrome)`。

​		此外还有一个 only 关键词，专门用于保证向后兼容

- **only**：在不支持媒体查询的旧浏览器中隐藏样式表。如，如果想在所有媒体中应用一个样式表，但是只在支持媒体查询的浏览器中应用，可以这样写：`@import url(new,css) only all`。在支持媒体查询的浏览器中，only 关键字被忽略，样式表会应用到文档上。而在不支持媒体查询的浏览器中，媒体类型为 only all，而这是无效的，因此不会应用样式表。only关键字只能用在媒体查询的开头。

##特性查询

​		2015~2016 年间，CSS 新增了一个功能：根据用户代理是否支持特定的 CSS 属性及其值来应用一段样式。这个功能称为特性查询（feature query）。

​		特性查询在结构上与媒体查询很像。假设想在用户代理支持 color 属性时为元素设定颜色

```css
@supports (color: black) {
    body {color: black;}
    h1 {color: purple;}
    h2 {color: navy;}
}
```

如果用户代理不支持 @supports，整段样式都会跳过。

​		特性查询是渐进增强样式的完美方式。比如想在浮动布局之外增加栅格布局，可以保留现有的布局方式，在样式表中添加以下内容

```css
@supports (display: grid) {
    section#main {display: grid;}
    /* 去掉旧布局的样式 */
    /* 栅格布局的样式 */
}
```

这段样式在支持栅格布局的浏览器中应用，它会覆盖旧的页面布局，然后应用通过栅格实现的新布局。不支持栅格布局的旧浏览器很可能也不支持 @supports，因此会跳过整段样式，就像没出现过一样。

​		特性查询可以嵌套，其实还可以嵌套在媒体查询中，而且反过来嵌套也可以。若想使用弹性盒布局编写针对屏幕和印刷媒体的样式，可以把媒体查询块放在 `@supports (display: flex)` 块里

```css
@supports (display: flex) {
    @media screen {
        /* 针对屏幕媒体的弹性盒样式 */
    }
    @media print {
        /* 针对印刷媒体的弹性盒样式 */
    }
}
```

反过来，也可以在实现响应式设计的媒体查询块中添加 @supports() 块

```css
@media screen and (max-width: 30em) {
    @supports (display: flex) {
        /* 针对小屏的弹性盒样式 */
    }
}
@media screen and (min-width: 30em) {
    @supports (display: flex) {
        /* 针对大屏的弹性盒样式 */
    }
}
```

具体如何组织完全由自己决定。

​		与媒体查询一样，特性查询也支持使用逻辑运算符。假如想在用户代理同时支持栅格布局和 CSS 形状时应用一段样式

```css
@supports (display: grid) and (shape-outside: circle()) {
    /* 栅格和形状样式 */
}
```

与下面的写法等效

```css
@supports (display: grid) {
    @supports (shape-outside: circle()) {
        /* 栅格和形状样式 */
    }
}
```

​		除了 and 之外，还有其他的运算符可用。CSS 形状体现了 or 的用处，因为很长一段时间以来，WebKit 只支持通过带厂商前缀的属性绘制形状。因此，如果想绘制形状，可以使用这样的特性查询

```css
@supports (shape-outside: circle()) or
    (-webkit-shape-outside: circle()) {
        /* 绘制形状样式 */
}
```

带厂商前缀的形状属性和不带厂商前缀的形状属性最好同时使用，但是上例这样做既能兼容 WebKit 以后的版本，也能支持其他无需使用厂商前缀的浏览器。

​		有时，想使用的属性与测试的属性不同。还以栅格布局为例，可能想在支持栅格时修改布局元素的外边距等：

```css
div#main {overflow: hidden;}
div.column {float: left; margin-right: 1em;}
div.column:last-child {margin-right: 0;}

@supports (display: grid) {
    div#main {display: grid; grid-gap: 1em 0; overflow: visible;}
    div#main div.column {margin: 0;}
}
```

​		此外，还可以使用取反运算符，如，在不支持栅格布局时应用

```css
@supports not (display: grid) {
    /* 不支持栅格时使用的样式 */
}
```

​		一个特性查询中可以使用多个逻辑运算符，但为了保证条理清晰，要使用括号。假如想在支持颜色的同时还支持栅格或弹性盒布局中的一个时应用一段样式：

```css
@supports (color: black) and ((display: flex) or (display: grid)) {
    /* 相关的样式 */
}
```

判断支持栅格或弹性盒的查询放在一对括号里。必须这么做，如若不然，整个表达式都将失效，而块中的样式则会跳过。也就是不要写成这样

```css
@supports (color: black) and (display: flex) or (display: grid) {
    /* 相关的样式 */
}
```

​		**为什么特性查询的测试中既要写属性也要写值**：毕竟，想使用形状时，只需要测试支不支持 shape-outside。这是因为浏览器可能支持某个属性，但不支持它的全部取值。栅格布局就是个很好的例子。如果像下面这样测试是否支持栅格肯定是不行的

```css
@supports (display) {
    /* 栅格样式 */
}
```

因为连 Internet Explorer 4 都支持 display。支持 @supports 的浏览器肯定支持 display 及其很多取值，但不一定支持 grid 这个值。鉴于此，特性查询既要测试属性也要测试值。

​		记住，这是特性查询，不是正确性查询。浏览器可能支持所测试的特性，但实现上有缺陷。所以，无法确保浏览器对特性的支持是否正确。特性查询得到肯定结果的意思很简单，表示浏览器支持想使用的特性，而且以某种方式实现了。

##总结

​		CSS 可以完全改变元素在用户代理中的表现方式。简单一点的，可能只是用 display 属性，复杂一点的则可以为文档关联样式表。用户绝不会知道使用的是外部样式表或嵌入样式表，抑或是行内样式。外部样式表的主要优势是，可以把一个网站的所有表现信息放在一个地方，然后在所有文档中指向这个位置。这样不仅便于更新和维护网站，还能节省带宽，因为所有表现都游离在文档之外。借助 `@supports()` 甚至可以使用纯 CSS 实现基本的渐进增强功能。

​		为了发挥 CSS 的作用，要知道如何把样式关联到文档中的元素上。若想完全理解 CSS 是如何做到这一点的，要充分掌握 CSS 选择文档中不同内容的方式。

# 选择符

## 样式的基本规则

​		CSS 的一个核心优势是可以为文档中某种类型的元素全部应用相同的规则。假如想让所有 h2 元素都显示为灰色。以前只能编辑 HTML，在每个 h2 元素中插入 `<font color="gray">...</font>` 标签。就算使用 style 属性，也省不了多少时间。要为每个 h2 元素设定 `style="color: gray;"` 属性。这样做效率不高又不灵活。CSS 样式便于修改和编译，而且能应用到指定的所有文本元素上。

### 元素选择符

​		元素选择符（element selector）通常是 HTML 元素，但也有例外。如，在针对 XML 文档的 CSS 文件中，可能有下面这些元素选择符

```css
quote {color: gray;}
bib {color: red;}
booktitle {color: purple;}
myElement {color: red;}
```

也就是说，文档中的元素是最基本的选择符。在 XML 中，什么都可以作为选择符，因为 XML 允许创建新标记语言，所以什么都可以作为元素名称。然而，为 HTML 文档编写样式时，选择符一般是 HTML 预定义的某个元素，如 p、h3、em、a，甚至是 html 自身。

​		直接为元素定义全局样式后，可以把样式从一个元素身上移到另一个元素身上。

### 声明和关键字

​		声明块中有一个或多个声明。声明的格式是固定的，先是属性，然后是冒号，后面再跟上值和分号。冒号和分号后面可以有零个或多个空白。值几乎都是一个关键字或以空格分隔的多个关键字。**如果声明中的属性或值有误，整个规则都将被忽略**。

​		如果属性的值可以是多个关键字，关键字之间通常以空格分隔，有时使用斜线或逗号。不是每一个属性都接受多个关键字，不过很多属性（如 font 属性）都是如此。这些以空格分开的词称为关键字，因为它们在一起构成一个完整而唯一的值。

​		CSS 关键字通常以空格分隔。在 CSS 2.1 中，有个特例：font 属性的值有一处要使用斜线把两个关键字隔开，举个例子如下

```css
h2 {font: large/150% sans-serif;}
```

这个斜线把设定元素字号和行高的两个关键字分开。font 声明只有这一个地方允许出现斜线，其他关键字都以空格分隔。

​		除此之外，其他一些属性的值中也可以使用斜线，比如

- background
- border-image
- border-radius
- grid
- grid-area
- grid-column
- grid-row
- grid-template
- mask-border

​		还有一些关键字以逗号分隔。声明多个背景图像、过渡属性和阴影时，相互之间以逗号分隔。此外，函数的参数，如线性渐变和变形函数，以逗号分隔。如

```css
.box {
    box-shadow: inset -1px -1px white, 3px 3px 3px rgba(0,0,0,0.2);
    background-image: url(myimage.png), linear-gradient(180deg, #FFF 0%, #000 100%);
    transform: translate(100px, 200px);
}
a:hover {transition: color, background-color 200ms ease-in 50ms;}
```

## 群组

​		想要把同一个样式应用到多个元素上时，可以使用多个选择符，或者把多个样式应用到一个元素或一组元素上。

### 群组选择符

​		可以放在一起的选择符数量没有限制，选择符以逗号进行分隔。群组可以在很大程度上压缩同类样式，这样得到的样式表更短。

#### 通用选择符

​		CSS 2 引入了一个新的选择符，名为通用选择符（universal selector），写作星号 `*`。要注意，通用选择符虽然便利，但是它的特指度是 `0-0-0`；而且由于目标元素是一切元素，可能出现一些意想不到的后果。

### 群组声明

​		一个规则可以有多个选择符，同理，也可以多个声明。即可以把多个样式写在一起。多个声明写在一起时，别忘了结尾的分号。浏览器会忽略样式表中的空白，因此必须保证句法正确，用户代理才能解析样式表。

​		严格来说。一个规则中的最后一个声明的结尾可以不带分号，但一般建议带上

- 首先能养成带分号的习惯
- 如果想在后面加一个声明，不用担心忘记补上分号
- 如果使用 Sass 这样的预处理器，所有声明通常都要求在结尾加上分号

​		与群组选择符一样，把声明写在一起也有助于保持样式表短小，意图明确，而且易于维护。

### 二者结合

​		选择符和声明都可以写在一起，二者结合，只需几个声明便能定义十分复杂的样式。选择符中除了同类元素外，还可以有其他元素。

### 在旧浏览器中使用新元素

​		HTML（如 HTML 5 规范）在更新的过程中加入了一些新元素。有些浏览器在这些新元素出现之前就已存在，因此可能无法识别新元素。如，在 Internet Explorer 9 之前版本中无法选择不支持的元素。解决方法是在 DOM 中创建元素，让浏览器知道元素的存在。

​		如 Internet Explorer 8 不识别 `<main>` 元素。使用下述 JavaScript 可以让 Internet Explorer 8 知道 main 的存在

```js
document.createElement('main');
```

运行这段代码后，旧版 Internet Explorer 将认识到元素的存在，从而允许选择并为之赋予样式。

## 类选择符和 ID 选择符

​		除了直接使用文档中的元素外，还可以使用类选择符和 ID 选择符，这样便能以一种独立于元素的方式赋予样式。这两种选择符可以独立使用，也可以和元素选择符结合在一起使用。然而，这两种选择符要求文档的标记有一定的结构，因此一般需要提前构思，做好规划。

### 类选择符

​		应用样式而不关心所涉及的元素，最常使用类选择符。为了把类选择符定义的样式应用到元素上，必须为 class 属性赋予适当的值。在 CSS 中，选择类的句法是在 class 属性的值前面加上点号 `.`。除了单独选择之外，还可以结合元素选择符。

​		使用 ID 选择符、类选择符、属性选择符、伪类选择符或伪元素选择符时，如果没有依附元素选择符，隐式蕴含通用选择符。还可以先使用通用的类选择符定义一个样式，然后再结合元素选择符。

### 多个类

​		根据 HTML 规范，class 属性的值可以是多个词，词之间使用空格分隔。词的顺序无关紧要。可以把两个类选择符串在一起，选择的是同时具有两个类名的元素，而且对类名的顺序没有要求

```css
.warning.urgent {background: silver;}
```

​		但这也不是表示类的顺序在任何情况下都不重要。

​		如果多个串联的类选择符包含 class 属性中没有的词，将无法匹配。

### ID 选择符

​		ID 选择符在某些方面类似于类选择符，不过有些重要区别。首先，ID 选择符的开头不是点号，而是个散列字元 `#`，也叫井号、哈希符号、哈希记号活三连棋棋盘。第二个区别是，ID 选择符引用的不是 class 属性的值，而是 id 属性的值。

​		与类选择符一样，ID 选择符中的通用选择符也可以省略。ID 选择符还有一个地方与类选择符相似：ID 选择符并不关心所用的元素。有时，可能知道文档中有某个 ID 值，但是不知道在哪个元素上。此时，可以直接使用 ID 选择符。如果唯一知道的是，每个文档中都有这么一个 ID，但是依附的元素不定，而且出现的次数不会超过一次，就可以使用 ID 选择符。

###类选择符还是 ID 选择符

​		类可以赋予任意个元素，但 ID 就不同了。在一个 HTML 文档中，一个 ID 能且只能使用一次。

​		实际上，浏览器不一定总会检查 HTML 中的 ID 是不是唯一的。也就是说，如果 HTML 文档中的多个元素具有相同的 ID 属性，相同的样式可能会应用到每个元素上。这是不正确的行为，但却可能发生。文档中出现多个相同的 ID 值还不利于 DOM 脚本编程，因为 getElementById() 等函数预期只有一个 ID 属性为指定的元素。

​		与类选择符不同，ID 选择符不能串在一起使用，因为 ID 属性的值不能是以空格分隔的列表。此外，用户代理判断改把哪个样式应用到元素上时，ID 选择符的权重更高。

​		此外还要注意，类选择符和 ID 选择符可能是区分大小写的，这取决于文档语言。根据 HTML 规范，类和 ID 的值是区分大小写的，因此类选择符和 ID 选择符的大小写必须与文档中的一致。

​		单纯从句法的角度来说，点号加类名的写法无法保证一定能用于 XML 文档。井号加 ID 的写法支持任何能确保文档内元素唯一性的文档语言。唯一性可以通过 id 属性确保，也可以通过其他任何方式，只要属性的值在文档中是唯一的即可。
